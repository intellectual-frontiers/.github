# Paper layouts: what they are, why they exist, and what the research found

For editors and authors. Read this when you wonder why a layout looks the way it does, which one to pick, or whether a paper's source has to change for it. The rules are in `0017-spoken-and-research-works`; the registry that drives the build is `latex/layouts.json`.

## In one paragraph

An author picks a page layout with one header line, `:layout: <name>`, and the paper's PDF is set in it. The layouts are the page grids of the best journals, measured from their own typeset pages, so the PDF holds the quality of HBR, NEJM, JAMA, Nature, and publications of that standing. Every layout shares one type, heading, box, colour, and reference design; they differ only in the grid. Nobody makes up a layout: not authors, not editors. There are twelve built layouts and two planned, and more are cheap to add, so an author who comes from a particular publisher can choose the layout that publisher's readers expect.

## How to choose

| If the paper... | Choose | Why |
|---|---|---|
| is text-led with a few small figures and tables | `two-column` (the default) | A balanced two-column page, a little more open than Nature. |
| must stay short in pages, or the author comes from Nature, Science, or PNAS | `two-column-dense`, `two-column-science`, `two-column-pnas` | Smaller type and tighter margins; `nature`, `science`, `pnas` are aliases. |
| comes from Cell, or has many figure panels | `two-column-cell` | A firm margin and 8.5 pt type that suit multi-panel figures. |
| will be read on screen, or by readers who want larger type | `two-column-large` | 10/12 pt, the largest two-column type (alias `circulation`, `aha`). |
| is short, text-led, and may be annotated | `two-column-wide-margin` | NEJM's open page with a wide inside margin (alias `nejm`). |
| is heavy in tables and figures, or in callouts | `single-sidebar`, `single-sidebar-compact`, `single-sidebar-left`, `single-sidebar-left-wide` | One main column, a sidebar for callouts, and exhibits across the full width. `jama` = `single-sidebar`; `elife` and `scirep` = `single-sidebar-left`; `plos` and `plosone` = `single-sidebar-left-wide`. |
| is almost all exhibits with short paragraphs | `single-narrow-margin` | The densest single column; about 105 characters per line, so not for long prose. |

When in doubt, leave the default. If a paper reads badly in its layout, change the layout, never the paper's source (see "Does the source change?").

## Typefaces

A layout is a page grid. Its typeface is a separate setting, so the same grid can be set in different type. The layouts all default to the house typeface (Source Serif 4 with Source Sans 3). A paper may choose another set with `:typeface: <name>` in its header, or a layout may name its own default (`latex/layouts.json`, `typeface`). Typeface sets live in `latex/typefaces.json`. A set that needs licensed fonts falls back to the layout's own typeface, with a note, when the fonts are not installed, so a missing licence never breaks a build.

**Why the house type differs from the journals'.** The journals use commercial or custom typefaces (NEJM: Quadraat and Scala Sans in custom builds; Nature: Harding Text; HBR: Guardian Text Egyptian and National, or Le Monde Journal; JAMA: Guardian Sans; The Lancet: Scala; BMJ: Meta Serif and Meta; PLOS ONE and Scientific Reports: Minion; eLife: Avenir; Circulation: Akzidenz-Grotesk). The house type is open-licence so it can be embedded, shipped in the repository, and built anywhere without buying anything.

**Closer open lookalikes.** Six open sets are built: `house`, `spectral`, `pt-serif`, `gelasio`, `charis`, and `lato`. They were chosen by comparing 52 open fonts with the journals' faces on measured letter widths and by eye (`typeface-comparison.md`). No open face is an exact match; the house face is already within a hair of the best open match for several journals.

**The real faces.** To set a paper in a journal's own type, license the family and install the files in ``fonts-licensed/` (a directory the consumer provides beside `fonts/`, never committed) (never committed), named as the registry's set expects (edit the names in `typefaces.json` to match your files). The sets are ready: `quadraat-scala`, `harding-graphik`, `guardian-national`, `guardian-sans`, `meta`, `minion-myriad`, `le-monde`. Some, such as NEJM's OTNEJM builds and Nature's Harding Text, may be custom to the publisher and not for sale; use the nearest family the foundry sells. Do not extract fonts from a published PDF: the embedded fonts are subsets, and their licences do not allow reuse.

## Sidebars

In a layout with a sidebar, pull quotes, practical-test boxes, notes and admonitions, and key callouts sit in the sidebar beside the text they follow. The layout decides, not the author; the author marks nothing. Colliding callouts stack down the sidebar. Key points and the status statement stay in the full-width band under the abstract (no reference puts them in the margin). A figure, a table, and the title block span the main column and the sidebar. In a layout without a sidebar the same callouts stay inline.

The build fails, with a message naming the paper and the layout, when a sidebar callout is too long to be placed (it is never dropped silently). It prints a warning when a callout was moved down the page and when a line is more than 2 pt too wide; read the warnings before release.

## Does the source change? Notes for authors and editors

Short answer: no. The same `paper.adoc` builds in every layout, and the first two papers (one two-column, one single-column with a sidebar) were built in all twelve with no source edit. The only layout setting is `:layout:`. What a layout can still affect, and what to do:

1. **Never refer to a place.** Do not write "the box below", "the figure above", "on the next page", or "see page 5". Layouts move callouts, floats, and page breaks. Name the item ("Figure 3", "the practical test for H2") or its section's title. Section numbers are not printed either, so refer to a section by its title (DD214 was changed for this on 2026-10-01).
2. **Keep callouts short in a sidebar layout.** A sidebar is 1.6 to 2.3 in wide. A callout of about a quarter of a page or more cannot sit there comfortably; the build warns when one is moved and fails when one cannot be placed. Shorten it, turn it into body text, or choose a layout without a sidebar.
3. **Long unbreakable strings** (a URL in a table cell, a long identifier) can run over a narrow column. Allow a break (a space or a zero-width break) or move the URL to the references. The build reports overfull lines.
4. **Tables.** Column widths are computed from the layout, and a table with three or more columns or much text becomes a full-width float in two-column layouts. No source change is needed. A table that needs more than about 9 columns at the narrowest layout may not fit; split it.
5. **Figures.** The SVG figures draw their text at about 10 pt at full width. At the narrowest layout (`two-column-wide-margin`, 6.45 in) the smallest figure text measured about 8.9 pt on the first two papers; at the widest, about 11.4 pt. No layout takes a figure under Nature's 5 pt minimum. Wide, short diagrams (the `*.print.svg` variants) read best in every layout; a tall figure in a single-column layout may leave white space.
6. **Math and code.** Display math is split to fit the column. Long code lines wrap. Check a long formula in `two-column-large` and `two-column-wide-margin`, the narrowest columns.
7. **Page count changes.** The two papers ran 8 to 10 pages (DD214) and 15 to 23 pages (CTO) across layouts. Do not state a page count anywhere.

If a future layout needs a source change, it is a defect in the layout: fix the class or the converter once, for every paper (0017 FR-030), and list the exception here.

### What the numbers say

- **Body type is small and the page is dense.** Every reference sets body text between 8 and 10 pt, with 0.5 to 0.9 in outer margins. A page with 1.1 to 1.3 in margins and 10.5 to 11 pt type matches none of them. That was the house single-column page before it was measured, and it looked like a children's book.
- **Two columns hold 40 to 65 characters a line.** The wide single columns (JAMA, PLOS ONE, eLife, Scientific Reports) run 76 to 89 characters and are always paired with a sidebar. Nobody sets one column across the whole page.
- **Wide figures and tables span the full text width, and in a sidebar layout they span the sidebar too.**
- **Sidebars exist in four forms:** a right side column (JAMA, PNAS first page), a left side column on every page (PLOS ONE, eLife, Scientific Reports, BMJ), an outer band alternating sides (The Lancet), and an occasional sidebar column (HBR).
- **In the journals the sidebar is mostly small.** The Lancet and BMJ bands hold the running head, the folio, short notes, and spanning exhibits. The house layouts use a wider sidebar (1.6 to 2.3 in) so that a callout fits; that is closer to HBR (1.75 in), PLOS ONE (2.28 in), and JAMA (2.15 in).

### What the publishers themselves publish

- **Nature**, Guide to preparing final artwork: figures 89 mm, 120 or 136 mm, or 183 mm wide; page depth 247 mm; sans-serif figure text; panel labels 8 pt bold; other text at most 7 pt and at least 5 pt.
- **NEJM**, Technical guidelines for figures: editable vector art; NEJM redraws every accepted figure. No column widths.
- **JAMA**: figures and tables up to 3.25 in (one column) or 6.75 in (two columns). From summaries by third parties; jamanetwork.com blocks automated fetches.
- **HBR**, Guidelines for authors: editorial standards only; no design specification.
- **Chicago Manual of Style and AMA**: not published-page standards. Their 12 pt, double-spaced, 1 to 1.5 in margin rules are for the author's manuscript. Applying them to a finished page gives an oversized look.
- No publisher was found to publish a page-design specification for its set pages. If one is found, replace the measurements for that journal with it.

### Limits of this research

- **Small samples.** One to four articles per journal, mostly from 2021 to 2022, interior full-text pages only. Figures are medians and can be off by about 0.02 in. Journals redesign; a new design needs a new measurement.
- **PDF versions.** The files are publisher-typeset PDFs from open access sources (PMC open data, nature.com, hosted HBR reprints). HBR's are magazine reprints from 2011 and 2012; today's `hbr.org` pages differ. The JAMA PDF is a Network Open article. The Lancet, Cell, and Elsevier PDFs are Elsevier's layout, not necessarily the printed journal's.
- **Typefaces: decision.** On 2026-10-02 Shahid kept the house faces as the default for every layout after a rendered review of four open lookalike sets (`typeface-comparison.md`, "Rendered review"). Authors can still choose a registered set with `:typeface:`.
- **Typefaces.** The references use licensed families (the table under Typefaces lists them from the PDFs themselves). The house uses Source Serif 4 and Source Sans 3, which are open licences. The layouts reproduce the grid; a typeface set closes some of the gap. That is why an alias such as `nejm` names a model and does not promise a match.
- **Journal names are used descriptively.** A journal name is a documented alias for "modeled on that journal's grid". The house does not claim the page is, or looks the same as, that journal's.

## How to add or change a layout

1. Measure the reference with `tools/render/pdf-measure.py file.pdf:pages`, on interior full-text pages.
2. Add an entry to `latex/layouts.json`: `cols`, `sidebar` and `sidebar_side`, `geometry` (a `geometry` package option string), type sizes, `span_in` (sidebar width, 0 for none), `col_in` and `wide_in` (widths for tables and figures), and the text fields (`summary`, `modeled_on`, `best_for`, optional `caution`). Mark it `built` only after the next two steps.
3. Run `tools/render/paper-layouts-check.sh` on each paper and read the pages. A layout is released when it builds for every paper and the rendered pages meet 0017 FR-030.
4. Run `tools/render/layout.py sync works/research/layouts/README.md works/research/design-reference.md` so the catalog here matches.
5. Record why in this file, and update the guide table above.

A change to the design itself (type, headings, boxes) is made once in `latex/ifarticle.cls` or the article converter, for every layout, and reviewed on rendered pages of one two-column and one sidebar paper first (0017 FR-030).

## Open items

- **`two-column-sidebar`** (aliases `hbr`, `lancet`, `bmj`): measured in The Lancet and BMJ on every page and in HBR on some. Not built: LaTeX places margin material beside a two-column text block unreliably. Needs a different technique (for example a `paracol` grid).
- **`three-column`** (Science Research Articles): not built; LaTeX has no native three-column mode that handles floats.
- **Review by eye of every layout on a paper with a long table and a wide figure**.
- **Typography**: a licence for any of the reference typefaces would let a layout match a journal's type as well as its grid (see Typefaces; the sets are registered and waiting for files).
- **Layout defaults**: every layout defaults to the house typeface. Setting a journal-modeled layout's default to its closest lookalike (for example `two-column-wide-margin` to `spectral`) is a design decision to make after reviewing the pages.
