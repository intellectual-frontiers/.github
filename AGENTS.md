# `.github` — agent entry point

This repository is small on purpose: the organization's public profile (`profile/`), the two machine setup scripts (`bin/`), `commons/` and its tests
(`tests/`). `commons/` holds what any company or harness of Intellectual Frontiers may use, with its own ontology, specifications and generated tables (see `commons/README.md`); a capability goes there when more than one harness should read the same facts. Its specifications are in `commons/spec-kit/`, not in a company's repository. The scripts' specification is `009-machine-bootstrap` in `erga`, the company's private monorepo, like every other specification of erga. Everything else (erga itself, its specifications, ontology and content) is in the private `erga` repository; do not add any of it here.

- Work spec first: change `009-machine-bootstrap` in `erga`, then the scripts, then the tests. Every requirement has a test or says why it has none.
- Run `python3 -m unittest discover -s tests` before you push (`.github/workflows/tests.yml` runs it on every push and pull request). It needs only the standard library (the `commons` generator's own tests also need `uv`, and are skipped without it), and a `Slim` test fails if a new top-level entry appears.
- A file under `commons/generated/` is generated (`uv run commons/tools/generate-packaging.py`): change the ontology under `commons/ontology/`, never the file, and run the tool before you push; a test fails where it is stale. The tool also writes the package table and the pins (`rustup-init`, `uv`, `fish` and the rest) between the marked lines of `bin/erga-setup.sh`. Commons specs are worked spec first, like every other (`commons/spec-kit/`).
- `bin/erga-bootstrap.sh` (the one that may use administrator rights) and `bin/erga-setup.sh` (which never does, and writes only inside one account's home folder) are POSIX `sh`, run from a pipe (`curl ... | sh`), and must stay readable by a newcomer. Each is one file with no data beside it; the bootstrap loads the setup's functions and runs the same file as the account. They install Rust through `rustup` (the clone's `rust-toolchain.toml` pins the version), copy `intellectual-frontiers/erga` to `~/workspaces/github.com/intellectual-frontiers/erga` and run only commands `erga` has. The setup writes no startup file: `erga shell ensure` does (erga's 010-shell), and the settings file it keeps must stay what `erga secrets` writes (erga's 011-secrets).
- Never put a secret, a token or a person's data in this repository: it is public.
