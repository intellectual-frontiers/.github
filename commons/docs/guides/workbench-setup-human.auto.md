# Set up as a person

Generated by `commons/workbench/tools/pages.ts` from the code of the library `workbench`; do not edit it.

You are a person: you may work in your own checkout or in worktrees of your own, you review and approve what an agent proposes, and you hold the gates that only a person may pass. The runbook below is generated from the contract of the commons (`bun run workbench project runbook` prints it).


Generated from the workbench contract; do not edit. Until 2027-01-01 the checks only give hints. After it they are prescriptive, and a safety rule (a secret in a file) always is.

## Set up your workstation

- [ ] Git is installed (`git`)
- [ ] Node 26 is the runtime of the checks and the backup of Bun (`node`)
- [ ] Bun, at the version the commons pins, runs the code, the tests and the dev loop (`bun`)
- [ ] Git has an identity, so that a merge is not made in another name (`git-identity`)
- [ ] origin/main is known, so that the loop can tell what a change touches (`origin-main`)

Then run `bun run workbench ready`. For the work you are about to do, `bun run workbench ready --for TASK --ensure` installs only what that task needs.

## Stages and how far an agent goes

- **develop**: agent-autonomous
- **safety-configuration**: agent-proposes; gates: scanner-pins
- **release**: agent-acts-human-reviews; gates: release-tag
- **rewrite**: human-only; gates: rewrite-published

## Gates: what only a person does

### release-tag

A release tag is signed by the releaser, from the commit that holds the release record. Approver: **releaser**, never the author of the change.

Record of the approval:

```
gate: release-tag
approver: <you>
author: <who made the change>
approved: <the hash of what you reviewed>
date: <day>
```

### scanner-pins

The pins of the secret scanner (the canaries) change only with the approver's say. Approver: **approver**, never the author of the change.

Record of the approval:

```
gate: scanner-pins
approver: <you>
author: <who made the change>
approved: <the hash of what you reviewed>
date: <day>
```

### rewrite-published

Rewriting published commits breaks every hash, tag and signature and is the releaser's. Approver: **releaser**, never the author of the change.

Record of the approval:

```
gate: rewrite-published
approver: <you>
author: <who made the change>
approved: <the hash of what you reviewed>
date: <day>
```

## Reviewing an agent's work

Open the agent's branch as a worktree of your own, beside the repository: `git worktree add ../<repo>.wt/<you>/review-<task> <branch>`. Read the hand-back report it left, run the checks, and approve or send it back.
