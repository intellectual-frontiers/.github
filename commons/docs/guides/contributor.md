# I want to change something

A change is made capability by capability, and each step leaves something a check can find.

1. **Start from a requirement.** Say what must be true in the library's own specification (`commons/<library>/spec-kit/specs/`), as a numbered requirement (`FR-nnn`) in a sentence that can be tested. Mizan's format is checked by `bun commons/tools/mizan-check.ts`; see [Mizan](concept-mizan.md).
2. **Write the test that proves it.** A test names the requirements it proves with `proves(["<spec> FR-nnn"], "what it shows", ...)` from the test library, and the file that holds it starts with a `// Spec:` line. A requirement with no test is a finding.
3. **Write the code.** Layers say where it goes: governance (what a thing is), logical (the model), physical (what runs). A library's `about.ts` lists its folders and what each may import, and the import check holds that table.
4. **Record how it is enforced.** `enforcement.tsv` names who checks each requirement; the generators write what follows from the models.
5. **Check it.** `bun run dev:check` at the root while you work; `bun run verify` in the library before you push. Versions are raised at the release, never by hand on every change; see [the release loop](concept-release-loop.md).

**Your first small task:** pick a library, add a missing `TSDoc` comment to an export that the API reference shows without a description, and run `bun run verify` in that library.

**Prove only what your change can break.** `bun run repoctl prove --why` classifies your change, runs the proofs it needs and says why each skipped proof is safe; see [proof by blast radius](proof-by-blast-radius.md).

## The rules every change follows

- **Spec first.** Change the specification (`274-agora` in `erga` for the installers, `commons/spec-kit/` for commons, a library's own `spec-kit/`), then the code, then the tests. Every requirement has a test or says why it has none.
- **TypeScript, strongly typed.** Bun is the default TypeScript 7 runtime and Node 26 the backup ([commons 0005-typescript-practice](../../spec-kit/specs/0005-typescript-practice/spec.md)). Every program and every test is TypeScript. A test is `<kebab-case>.test.ts` written with the library `test` (`@intellectual-frontiers/test`, `proves`), found by `bun test` and `node --test` with no configuration. A library's tests are in its `suite/` and run by its `verify`; the tests of the root are in `tests/`, type-checked by `tests/tsconfig.json`. Every `tsconfig.json` extends `commons/tsconfig.base.json`, and `bunfig.toml` at the root holds the settings of `bun fmt` and `bun lint`. Commons' tools (`commons/tools/`) parse options once at the boundary, use discriminated unions with an exhaustive `switch` (`default: return absurd(x)`), return errors as values (`Result`), and have no `any` and no non-null `!`; the one cast is `brand` in `core.ts`, and the typing test checks it. The ontology is TypeScript (`commons/ontology/`, [0012-ontology](../../spec-kit/specs/0012-ontology/spec.md), typed by the RDF library), decoded once into typed records, with Turtle generated and never a source; findings are a union with one sentence each. The tools import nothing outside `commons/tools/` but the ontology, the TOML reader of `formats` and two built-ins of `node:`.
- **Tests run the real programs.** Real `git`, real `sh`, the real tools, never a stand-in for Git or the GitHub CLI (a remote is a real temporary repository). What needs an account, a browser or administrator rights is left untested, and the header of the test says so.
- **A generated file is never edited.** A file under `commons/generated/` is changed through the ontology under `commons/ontology/`, and `bun run repoctl sync` makes every generated file, in dependency order, and only the stale ones; a test fails where one is stale.
- **Documentation is the code's** ([0011-documentation](../../spec-kit/specs/0011-documentation/spec.md)). `commons/docs/` is the library Docs; it reads the TypeScript and the spec kit that `docs.config.ts` names. Commons keeps no README per library: a module's documentation is its TSDoc (the module comment says what it is, `@remarks` the longer account, `@limits` what it does not do), and an area's typed facts are its `about.ts`. Change the documentation in the same commit as the code, in the module it is about. `bun run verify` in `commons/docs` runs before you push; `bun src/main.ts build --out ../../_site` builds the site, which is never committed; `--presentation web,markdown,data` is the site, and `bun src/main.ts build --presentation book --out DIR` writes the AsciiDoc of the volumes of the Commons Manuals (`DIR/<volume>/generated/<volume>.adoc`; `--check` compares without writing). The table of the libraries in the root `README.md` is generated between `<!-- libraries-map:begin -->` and `<!-- libraries-map:end -->` by `bun commons/libraries/src/readme.ts`; run `bun run repoctl sync` after a manifest or an `about.ts` summary changes, and write the rest of the README as what is true now. The explanation of Mizan is the group Mizan of the Concepts section (`commons/docs/guides/mizan-*.md`).
- **Acceptance kits.** A library may keep testing by people or agents, for the experience beyond the code, in `acceptance/` (or `oat/`, `uat/`, `aat/`): kits with made-up data, each a folder with its README and findings and its own checks, and one spec kit of their own beside them (`acceptance/spec-kit`, numbered from 0001). A kit is not a library, is never moved into the library's `suite/`, and is run apart (in `commons/data`, `bun run acceptance`; the first kit is `commons/data/acceptance/arcactl-pg`). The three tiers of specifications (the repository's, the library's, the kits') only cite upward ([0027-commons-libraries FR-025](../../spec-kit/specs/0027-commons-libraries/spec.md)).
- **License.** Every library and every part of this repository is under the PolyForm Noncommercial License 1.0.0 (`PolyForm-Noncommercial-1.0.0`, licensor Intellectual Frontiers LLC; commercial use needs the owner's paid license; [0035-licensing](../../spec-kit/specs/0035-licensing/spec.md)). `bun commons/libraries/src/license.ts` writes the `LICENSE` of the root and of every library folder and `THIRD_PARTY_NOTICES.md`, and `--check` fails where any is wrong; `bun run repoctl new library <name> --summary "..."` scaffolds a library, its `LICENSE` included. Never write a license text by hand.
- **Never put a secret, a token or a person's data in this repository: it is public.**
