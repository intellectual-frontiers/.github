# Converge settings

## When to use

Bring the settings of a system of record to the settings that are wanted: observe both, diff them, plan the changes, have a person approve the plan by its hash, apply it once and verify.

Form: reconcile. Started by: a schedule, daily.

## How to run it

You orchestrate: every effect is a verb of the pinned packages, called by its id as `bun run workload verb <id>` and never by a command built from the text of a node. A `judge` only proposes: record what it proposes and apply nothing from it. At an ask or a gate stop and hand back: a person answers, and you never approve your own work. A reconcile is a loop toward a desired state and is level-triggered: each pass starts from what is observed now. The plan is approved by its hash; if the plan changed since a person approved it, it is not approved and you stop and hand back.

## Inputs

- none

## Verbs

- `state.apply` (@intellectual-frontiers/workload): Apply the changes of an approved plan to a store, once, by the hash of the plan as its idempotency key; the host that has the system binds it; the strictest autonomy of its nodes is human-only
- `state.observe` (@intellectual-frontiers/workload): Read the state of a store as named values, for a loop that observes the actual or the desired state; the host that has the system binds it; the strictest autonomy of its nodes is agent-autonomous
- `state.verify` (@intellectual-frontiers/workload): Read the state of a store and say whether it matches the state of another store, for a loop that verifies it converged; the host that has the system binds it; the strictest autonomy of its nodes is agent-autonomous
