# Feature Specification: Asset connections

**Spec ID:** 0044-asset-connections
**Status:** Draft
**Owner:** if
**Domain:** commons
**Part of:** 0041-telemetry-and-reach

**Input:** An estate is not a list of machines that someone enrolled one at a time. A cloud account holds thousands of resources, an identity provider holds every account, a code host holds every repository, a cluster holds workloads that appear and disappear, and a site relay hears every device on a LAN. A **realm** is where assets are found; where they are accountable is a **boundary** (0045-boundaries), which is a different thing and is never the scope of a connection. The unit that a person decides about is therefore the **realm** (a cloud account, a subscription, a project, a SaaS tenant, an identity provider, a code host organization, a device-management service, a Kubernetes cluster, a virtualization manager or a site relay), and the object that carries the decision is a **connection**: one approved, typed, read-only link from the controller to one realm, with a policy (scope, classes, retention, cadence, budget), credentials held by name, and a plan that a person approves by its hash. Assets inside an approved realm join the register by policy, and every asset is seen by as many sources as there are (a cloud API, infrastructure as code, a login, SNMP, a device-management service, DNS, a flow log), merged by identity, so that a difference between sources is itself a finding. This specification states the connection, the register of assets from many sources, populations of assets that appear and disappear, the credentials and the generated plan that connects an account, the permissions and the health of a connection, ingestion of tools that read best (pinned, typed, run as workloads), event streams and change feeds, and declared against observed drift of cloud resources in the one algebra of Desired OS State. It invents no connector contract, no codec set, no scanner runner, no identity function and no drift algebra: it joins what `integrations`, `scanners`, `findings`, `estate`, `estate-iac`, `desired-os-state`, `telemetry`, `tenancy`, `workload` and `ssh-server` already have (the reuse audit, `reuse-audit.md`, row by row). **Every requirement that asks for code is Deferred: this specification and the ones it governs hold no code.**

## The connection

- **FR-001**: A connection MUST be a typed value `{ id, kind, realm, connector, credentials, policy, plan, approval, state }`: its id (lower case words joined by hyphens), its kind (FR-002), the realm it reads (FR-003), the connector by id and pinned version (FR-080), the credentials by name (FR-041), the policy (FR-004), the plan that connects it (FR-043), the approval (FR-006) and the state (FR-005). A connection MUST be a document of the fleet repository (`connections/<id>.json`) that holds no secret, no token and no endpoint that is not public, and it MUST be checked on read by the same decoders as every other document of the fleet (estate 0005-estate-fleet-documents). Relies on audit rows: B1, B3, B7.
- **FR-002**: The kinds of connection MUST be one closed table that only grows: `cloud-account` (an account, a subscription or a project of a cloud, with its organization where one exists), `saas-tenant` (a tenant of a service the organization uses), `identity-provider`, `code-host` (an organization or a group), `device-management` (the service that manages endpoints), `cluster` (a Kubernetes cluster), `virtualization` (a manager of virtual machines), `directory` and `site-relay` (a relay and the LAN it hears). Each kind MUST name the classes of asset it may bring into the register (0043-asset-properties FR-029) and the paths it reads by (0043 FR-006). A class that a kind does not name MUST NOT be brought in by it. Relies on audit rows: B1, H1.
- **FR-003**: A realm MUST be a typed identifier made only by a smart constructor that validates and normalizes it (`provider`, `kind`, `identifier`): the identifier of a cloud account, subscription or project; a tenant identifier; the host of a code host and its organization; the identifier of a cluster; the id of a relay. A connection MUST NOT read outside its realm, and a read that returns an asset whose own identifier names another realm MUST be refused and counted (`E-CONNECT-OUT-OF-REALM`). Relies on audit rows: B1, D1.
- **FR-004**: The policy of a connection MUST be typed data of: the scope (include and exclude by region, resource type, tag, name pattern or folder, never a free text query), the classes it may bring in (FR-002), the properties it reads (0043 FR-001), the cadence per property class (0043 FR-021), the retention of readings and evidence (a time, and whether whole chains are archived), the budget (FR-053), the auto-enrol rule (FR-034) and the approvers by role. A policy MUST NOT be able to widen a connection beyond what its plan was approved for: a change of scope, classes or budget MUST be a new plan with a new hash (FR-006). Relies on audit rows: B1, B6.
- **FR-005**: A connection MUST have exactly one state of the closed, ordered table `proposed`, `approved`, `connecting`, `active`, `degraded`, `suspended` and `retired`, changed only by the typed events `approved`, `connected`, `degraded`, `recovered`, `suspended`, `resumed` and `retired`, each written once to the connection's journal (a chained, append-only record) with its actor, and the state MUST be a fold of the journal. A `suspended` connection MUST read nothing and MUST keep its assets and readings; a `retired` one MUST read nothing, keep its evidence for the retention of its policy, and have its assets marked `unmanaged-by-connection`, never deleted. Relies on audit rows: B7, E1.
- **FR-006**: A person MUST approve a connection by the hash of its plan (FR-043): the approval MUST show the realm, the connector and its pin, the policy, the permissions it will need (FR-050), the budget and what a first read will cost, MUST name the approver and their role, and MUST be a person's act in the local channel that an agent, a script and a pipe cannot make (`E-CONNECT-NOT-PERSON`). An agent MAY propose a connection and MAY read the proposal, and a proposal MUST change nothing and read nothing from the realm. A connection whose plan hash changed since approval MUST NOT read until it is approved again. Relies on audit rows: B7, E2.
- **FR-007**: Every connection MUST belong to a party that the fleet serves and to an engagement that allows it (`tenancy`: the parties, the engagements with their roles and dates, deny-by-default authorization), so that a provider of managed services holds each client's connections apart, a principal reads only the connections of the clients it may, and a connection MUST NOT be approved, resumed or read outside the dates of its engagement. Relies on audit rows: B6.
- **FR-008**: A connection MUST be readable by a person at any time as one typed document (`connection-status`: its state, its health (FR-052), its permissions and their drift (FR-051), its budget used, its last read, the assets it brought and their coverage (0043 FR-019)), and the same document MUST be what every surface prints. Relies on audit rows: B1, H3.

## Assets from many sources

- **FR-030**: The register MUST hold every asset any source names, whatever its tier (0043 FR-024): an asset named only by infrastructure as code, only by a cloud inventory, only by a login, only by SNMP, only by a device-management service, only by DNS or only by a flow log is in the register with the sources that named it and its tier, and an asset is never left out of the register because no probe can read it yet. Relies on audit rows: D1, D3.
- **FR-031**: Identity MUST be resolved by `resolveIdentity` of the estate over **identity keys** that are the closed union of estate 0009-estate-sightings FR-004 extended with `cloud-id` (the provider's own canonical identifier of a resource: an ARN, a resource identifier of a subscription, a self link of a project, made by a smart constructor that lower-cases what the provider says is case-insensitive and nothing else), `device-uuid` (a managed device's identifier from a device-management service), `k8s-uid` (the UID of an object with its cluster), `repo-url` (the normalized URL of a repository), `dns-name` (weak) and `principal-id` (an identity of a provider), each strong or weak as stated in the table of the library; keys MUST only grow, and a key held by two assets MUST be a finding that a person settles and MUST never be merged by the controller. Relies on audit rows: D1, D2.
- **FR-032**: Each class MUST declare, as data, the sources it is **expected** to be seen by (the profile of 0043 FR-009): a laptop by a device-management service and by the network; a cloud virtual machine by its provider's inventory, by infrastructure as code and by a login; a switch by SNMP and by the LAN; a repository by the code host; and a policy MAY tighten the list for a connection or a client. An expected source that has not seen an asset within its cadence MUST be a finding of kind `source-missing` that names the source. Relies on audit rows: D1, D3.
- **FR-033**: The differences between sources MUST be findings of the closed, growing table `SourceDifference`, each with the sources it compares and the asset, and each opened and resolved by the evidence only: `in-cloud-not-in-code` and `in-code-not-in-cloud` (the drift of FR-070), `on-network-not-in-register` (estate `unexpectedDevices`, estate 0009 FR-008), `in-register-not-seen-by-any-source` (a ghost, after the time of the policy), `managed-not-seen-on-network`, `on-network-not-managed`, `in-identity-provider-not-in-register`, `in-register-without-owner` and `source-missing` (FR-032). A person MAY accept a difference for a time and a reason by the owner's typed accepted-finding file, and an agent MUST NOT write it. Relies on audit rows: D1, D4, D5.
- **FR-034**: An asset reported by an authenticated source of an approved connection MUST join the register by policy, with the trust `connected` (enrolled by the policy of a connection that a person approved, naming the hash of its plan), at tier `1` or higher by its reach, and MUST NOT need one approval each: the assets of a cloud account, a tenant, a code host, a cluster, a device-management service and a virtualization manager, and a device read by an SNMPv3 or Redfish poll whose credential is the connection's. An asset seen only through an unauthenticated source (a syslog source address, an ARP or neighbour entry, a NetFlow exporter) MUST remain a sighting that a person approves (estate 0009 FR-011), whatever the policy says. The trust word MUST be recorded and shown, and MUST NOT be shown as the trust of a person's pairing. Relies on audit rows: D1, B1, B5.
- **FR-035**: A connection MUST bound how many assets it may bring in without a person: a count per day and per scan in the policy (a default and a maximum); the assets beyond it MUST be listed as pending with the evidence, MUST NOT be read, and MUST raise a finding of kind `enrolment-flood`, so that a misconfigured scope or a realm that suddenly holds ten thousand resources cannot fill the register unseen. Relies on audit rows: D1, B6.

## Populations

- **FR-036**: A **population** MUST be an asset of the kind `population` (0043 FR-029) that stands for a group of ephemeral members that a realm creates and destroys by rule (an autoscaling group, a node pool, a deployment's pods, a fleet of functions, a managed instance group): it has a kind, the identifier of the group, the template or rule it comes from (a reference to the declaration), the expected size range and the policy for its members; and its members MUST be recorded as observations of the population (`member-of`) and never as separately enrolled assets. Relies on audit rows: D6, D1.
- **FR-037**: The lifecycle of a member MUST be the typed events `appeared` and `disappeared` with the instant each was seen and the reading that showed it, written once and folded into the population's state; a member that disappeared MUST keep its readings for the retention of its policy as evidence of what was true while it lived, and MUST NOT remain in the register as a live asset. Relies on audit rows: D6, A9.
- **FR-038**: The judgement of a population MUST be over its members: the share of live members whose required properties are fresh and passing (its coverage, 0043 FR-019), the number that appeared and disappeared in the period, and the members that failed, and a finding about a member MUST name the member and the population; the population itself is what a control is evidenced against and what a view counts, so that a thousand identical short-lived nodes are one asset with a coverage and not a thousand records. A population whose template changed MUST show the difference between its template and its observed members as drift (FR-070). Relies on audit rows: D6, E3.
- **FR-039**: A member MUST be given the identity keys of its provider (FR-031) and MUST NOT be merged with another asset by a weak key alone; a member that carries a login (a virtual machine of a scale set) MAY be read by it, and its tier MUST be the highest path that worked (0043 FR-023). Relies on audit rows: D1, D6.

## Credentials, keys and the plan that connects an account

- **FR-040**: A connection MUST hold a **signing identity** that is a key held by the controller (a key of its own for the connection, held in the controller's key store, never in a repository), and every reading the connection makes MUST be signed by it (0043 FR-011); revoking the connection MUST revoke the key. Relies on audit rows: F1, A5.
- **FR-041**: A credential MUST be held only by name: the connection document and its plan MUST name `vault://<store>/<name>` references or the names of environment variables and MUST hold no value; the credential port MUST give a `Secret` that prints `[secret]` however it is turned into text and gives its value only to `reveal` at the instant of the call (integrations 0003-integrations-logical FR-002); no value MUST appear in a plan, a trace, a finding, a log or an error. Relies on audit rows: F1, B3.
- **FR-042**: A connector MUST prefer a credential that is short lived and federated, in this order: (1) a role assumed through the person's own sign-in session by profile name (an interactive sign-in the person has already made with the provider's tool); (2) workload identity federation, where the controller runs where it has an identity the provider trusts (an OpenID Connect token of its runner, a certificate the provider accepts) and exchanges it for a token of the least lifetime the provider allows; (3) a long-lived key by name, which MUST be flagged `credential-long-lived` with its age and MUST be a finding when older than the policy allows. A connector MUST state which of the three it supports for each provider, and where none is known the connector MUST say `UNVERIFIED` (see UNVERIFIED). Relies on audit rows: F1, F2.
- **FR-043**: The **plan** of a connection MUST be generated by the SDK and MUST contain, as typed data with a hash: the realm, the connector and its pin, the policy, the permissions the connector needs as data (FR-050), and the **connect module**, a pinned module of OpenTofu (the dialect of `desired-os-state-opentofu`: a configuration with pinned providers, no credential, and state kept outside the repository) that creates, in the realm and by the hand of its administrator, the one read-only role, service principal or service account that the connector reads as, with the trust relationship to the controller's identity (FR-042) and the permissions of FR-050 and nothing else. Relies on audit rows: F3, E4.
- **FR-044**: The controller MUST NOT need, hold or ask for the right to create a role or a principal in a realm: the connect module is given to the party that administers the realm, who reviews and applies it with their own rights (and MAY be a person of the same organization or of the client), and the controller MUST only verify the result (FR-045). A plan MUST say plainly that it asks nothing of the controller beyond a read. Relies on audit rows: F3.
- **FR-045**: Verification MUST be one typed step `connect verify`: the connector's `probe` runs, reads the one identity it connected as, lists the permissions it holds (FR-051), and the connection becomes `active` only if the role is the one the plan names, reachable, read-only and not broader than the plan (`E-CONNECT-NOT-VERIFIED` otherwise, naming what is wrong and the part of the module to correct). Relies on audit rows: B1, F3.
- **FR-046**: A credential that is a long-lived key MUST have a rotation age as policy data, and the connector MUST read the age where the provider says it (the creation date of a key) and open `credential-near-expiry` before it passes; a credential that a connector can no longer use MUST put the connection in `degraded` and never hide it. Relies on audit rows: F1.

## Permissions, health and cost

- **FR-050**: Each connector MUST state as data the permissions its reads need (`permissions`): for each operation the provider's own name of the action or scope, whether it reads metadata or content, and the property of 0043 it serves, derived from its governance so that it cannot differ from what the connector does (as `describe` is, integrations 0005-integrations-observe FR-003), and the plan's role MUST be generated from it and from nothing else. A connector MUST NOT list a permission that can write, delete, start, stop, assume another role or read the content of data (as opposed to its metadata) unless its policy names that the property needs it and a person approves it by name. Relies on audit rows: B1, F3.
- **FR-051**: The **permission drift** of a connection MUST be checked on each verify and on a cadence: the permissions the identity actually holds (read from the provider where it can say) compared with those of the plan, and a permission broader than the plan (any write, any permission outside the list) MUST be a finding of kind `permission-too-broad` of high severity that degrades the connection, and a missing permission a `denied` gap on the properties that need it (0043 FR-004). The check MUST itself be read-only. Relies on audit rows: B1, F3.
- **FR-052**: The health of a connection MUST be one typed document of: reachable, permitted (FR-051), the share of expected readings that are fresh (its coverage), the last successful read, the errors by code, the budget used (FR-053) and the age of its credential (FR-046); and a connection whose coverage is below the policy MUST be `degraded` with the reason. A connection that is healthy but has read nothing new MUST show its freshness as such and MUST NOT show as healthy by being reachable alone (0043 FR-019). Relies on audit rows: B1, A4.
- **FR-053**: A connection MUST have a **budget** in its policy: the calls, the bytes and the concurrency it may use per day against the provider's own limits and cost, and the plan MUST show the estimate of what the cadences and the scope cost in calls per day before approval (a connector states its calls per operation as data, `cost`); a read MUST stop when the budget is spent and the rest MUST be read when it renews, and no read MUST be made over the budget. Relies on audit rows: B1, G3.
- **FR-054**: A connector MUST back off on a throttle or a server error as the provider says (honouring its retry hint), with a bounded exponential back-off and jitter, MUST read through the provider's list operations with the largest page the provider allows, and MUST read changes where a feed exists (FR-062) before it re-reads everything. Relies on audit rows: B1, G3.
- **FR-055**: A budget that is spent or a read that cannot be made MUST degrade and never skip: the cadence of the least important properties (by the policy's order) is lengthened first, the readings that cannot be refreshed become `stale` by their cadence (0043 FR-020) and the connection is `degraded` with the reason `budget`; nothing MUST silently hold an old reading as fresh. Relies on audit rows: A4, G3.

## Ingestion of the tools that read best

- **FR-056**: An **ingest source** MUST be a typed value `{ id, producer, pin, command, codec, class, authenticity, connection }`: the tool or the provider's read operation that produces the data, its exact version and the SHA-256 of its binary (`pin`, the pinned download of `desired-os-state-pinned-downloads`), the typed argv it is run with (read-only operations only, no shell, FR-057), the codec that reads its output (FR-059), the class of asset it speaks of, the authenticity its readings have (`ingested`, 0043 FR-012) and the connection (FR-001) whose realm and credentials it runs under. A reading from an ingest source MUST name its producer and pin and MUST be signed by the controller that ran it, and the producer's own output MUST be kept by its digest as evidence. Relies on audit rows: C1, C3, A5.
- **FR-057**: An ingest source that runs a program MUST run it as `scanners` runs a scanner: only after the engagement allows the action, only a binary whose SHA-256 is the one pinned, with a command line made from validated parts and no shell, in an empty working folder, with the credential injected for the one run as the connection's `Secret`, with a time and an output limit, and without a way to write to the realm (a tool that can change a realm MUST NOT be an ingest source). The provider's own inventory operations (the Config, Resource Explorer, Resource Graph and Cloud Asset Inventory reads) MUST be ingest sources whose program is the provider's own command-line tool at a pin, with a read-only argument list that the connector states. Relies on audit rows: C1, C3.
- **FR-058**: The licence of a tool MUST be a field of its pin (`licence`, an SPDX identifier, read at the pin and recorded with the source it was read from), and a tool MAY be run only by this rule: a permissive licence (Apache-2.0, MIT, BSD-2-Clause, BSD-3-Clause, ISC, MPL-2.0) MAY run; any other licence (an affero, server-side, business-source, elastic or non-commercial licence, or an unknown one) MUST be refused (`E-INGEST-LICENCE`) until a person records a review of it, with the reasons, as the owner's typed review file; and a tool of ours MUST NOT bundle, link, copy or redistribute a tool run this way: it is fetched from its publisher by its pinned address and run as a separate program. A tool that can act on a realm (remediate, delete, change) MUST be refused as an ingest source whatever its licence. Relies on audit rows: C1, C3, C7.
- **FR-059**: An ingest source's output MUST be read by a typed codec of a plugin of `integrations-standards` (integrations 0008-integrations-plugins), which MUST give the same abstract tree on a repeated read and fail with a code and an offset and no part of the text: the codecs for OCSF (the schema of the records already used by connectors, `ocsf_class_uid`), SARIF (read by `findings`), CycloneDX and SPDX (software bills of materials), OSCAL assessment results, the JSON of a provider's inventory operation, and the rows of a tool that gives rows (as JSON lines). A codec MUST be proved by the conformance suite over synthetic samples or the published examples of its standard whose licence allows it. Relies on audit rows: C4, C5.
- **FR-060**: An ingest MUST be run as a workload of the form `runbook` (workload 0008-form-runbook): a step that fetches the pinned tool (the pinned download), a step that runs it read-only under the connection, a step that decodes its output with the codec and a step that writes the readings and the assets, each with its effects and its receipt; the run is scheduled by the cadence of the properties it feeds (0043 FR-021), runs under the autonomy of its steps, and an agent MAY start it only where its connection is approved. Relies on audit rows: C6.
- **FR-061**: The candidates considered MUST be recorded with the decision, and the decision of a tool MUST be reviewed at its pin (FR-058); the first table is in the section "Ingest candidates" below. Relies on audit rows: C1, C7.
- **FR-062**: A **change feed** MUST be a typed capability of a connector (`changeFeed`): the provider's stream of change events of a realm (an event bus of rules on resource changes, an event grid, an asset feed), which the connector reads or which a connection's plan sets up to deliver to the controller's receiver (a plan step, in the connect module, approved with the rest); an event MUST mark the readings of the properties it touches `stale` and queue one targeted read (0043 FR-022), and MUST be a reading itself only where its path is `event`. A connection with no feed MUST poll by cadence under its budget (FR-053), and MUST say so in its health. Relies on audit rows: G2, G3.

## Event streams

- **FR-063**: An **event source** MUST be a typed value of the closed, growing table `cloud-audit` (the audit log of a cloud account), `identity-audit` (sign-in and administrative events of an identity provider), `saas-audit` (the audit log of a tenant or a code host), `flow-log` (network flows of a cloud network), `endpoint-audit` (events of a device-management service) and `lan-passive` (DHCP, ARP, neighbour tables, syslog, NetFlow and IPFIX heard by a site relay), each with its connector or relay, its codec and its mapping. Relies on audit rows: G1, G4.
- **FR-064**: An event MUST be mapped to the same `SignalRecord` of telemetry (telemetry 0001-telemetry) with the asset it is about, the class of the event in OCSF (the class and activity of the record), its time as claimed and its receive time, so that every path of every class reaches the estate through one mapper; an event whose asset is not in the register MUST become a sighting or a source of `on-network-not-in-register` and MUST NOT be dropped. Relies on audit rows: G1, D3.
- **FR-065**: An event stream MUST be kept as evidence by digest and count, never by content: a batch of events is stored once as a redacted file whose digest and count go in the evidence chain, and the readings that the events give (`event`, 0043 FR-006: a sign-in without multifactor authentication, an administrative login by a root account, a logging setting turned off) are the typed readings that a control reads; the redactor MUST remove a secret, an address of a person and a personal datum before anything is stored. Relies on audit rows: G1, A9.
- **FR-066**: The passive sources of a LAN (`lan-passive`) MUST be heard at the site relay as 0041-telemetry-and-reach states, and what they say MUST be an `unauthenticated` source (0043 FR-012) that opens a sighting and never an asset by itself (FR-034); a relay that polls with a credential (SNMPv3, Redfish) is an authenticated source and its assets MAY join by policy (FR-034). Relies on audit rows: G4, D1.

## Declared, observed and authoritative

- **FR-070**: The drift of a cloud resource MUST be the same value as the drift of a host: the plan that `driftOf` of `desired-os-state` gives over the requirements of an order (one difference for each requirement, with what was expected and what was observed) and its `DriftSummary`, for requirements of the kinds `cloud-resource` and `dns-record` whose subject class is `cloud-account`; the comparison of `estate-iac` (`driftBetween`, its `Drift`) MUST be stated in that one value and not be a second one; and the three sources MUST be named: **declared** (a requirement, or the infrastructure as code that `estate-iac` reads), **observed** (what a connector or an ingest source read of the realm now) and **authoritative** (FR-072); the comparison MUST be one function that gives, for each resource, `not-in-cloud`, `not-in-code`, `region-differs`, `settings-differ` or in agreement, and a resource of a provider and type the code does not cover MUST NOT be `not-in-code` unless the whole account is asked for (estate-iac 0004-estate-iac-drift FR-001, FR-002). Relies on audit rows: E1, E3, E5.
- **FR-071**: Observation of a cloud-resource requirement MUST be an adapter, as the osQuery adapter is for a package: a function from the rows a connector or an ingest source gives (the provider's inventory read, FR-057) to the observed state of the kinds the provider can say, and a kind it cannot say MUST be not watched and never drift (desired-os-state 0007-desired-os-state-observe-osquery FR-003 states the same for osQuery). Relies on audit rows: E1, E3.
- **FR-072**: Each attribute of a requirement MAY have an **authority** in its policy: `declared` (the code is right and a difference is a change to undo), `observed` (the cloud is right and a difference is a change the code must take, as with a tag a console adds) or `either` (a difference is to be settled by a person); the default MUST be `declared`, and the authority MUST be data in the fleet repository, reviewed with the rest. A difference whose authority is `observed` MUST NOT be a failure of the resource, and MUST be a finding of the code. Relies on audit rows: E1, E5.
- **FR-073**: The reading `configuration-matches-declared` (0043 FR-003) of any class MUST be the judgement of the drift of its requirements (FR-070), whatever the class, so that "does the asset match its declaration" is one property with one value over hosts, cloud resources, clusters and tenants. Relies on audit rows: E1, A1.

## The connector contract

- **FR-080**: The contract of a connector MUST be the `Connector` of `integrations` (integrations 0005-integrations-observe: `describe`, `probe`, `observe`, governance enforced on what it returns, posture policies, a registry that pins connectors by tag and a conformance suite), extended by `permissions` (FR-050), `cost` (FR-053), `changeFeed` (FR-062, optional), the paths it reads by (0043 FR-006) and the properties it reads (0043 FR-001); no second contract, no second registry and no second conformance suite MUST be made, and a connector for a class of realm MUST be a library `integrations-<vendor>` of commons with its own spec kit (integrations 0008-integrations-plugins FR-001, integrations 0010-integrations-network-observers FR-001). Relies on audit rows: B1, B2.
- **FR-081**: `conformConnector` MUST also find a connector whose declared permissions differ from the operations it calls, one that can write, one that reads content where it declared metadata, one whose cost is not stated, one that returns an asset outside its realm, one whose observation is not the same when repeated, and one that exposes a credential in any output. A connector that does not conform MUST NOT be registered, and a registered one MUST be pinned by its tag and its digest. Relies on audit rows: B1, B2.
- **FR-082**: A connector of a realm MUST give, besides its observation, the **discovery** of the assets of the realm as assets of the catalog (0043 FR-029) with identity keys (FR-031), their links (`contains`, `member-of`) and their provenance (`<connection>/<operation>#<identifier>`), and a connector MUST NOT make an asset of a kind its connection's kind does not name (FR-002). Relies on audit rows: B1, D1.
- **FR-083**: Native connectors MUST be written only for a read that no pinned tool does better or where a tool cannot run read-only; the reads of the inventory of a cloud, a cluster and a tenant MUST first be ingest sources (FR-056 to FR-060), and a native connector MUST be added for a hot path only, where the cadence, the cost or the permissions of the ingest are worse than a connector's (a measured reason in its spec). The connectors that exist (`integrations-github`, `integrations-identity`, `integrations-snmp`, `integrations-redfish`, `integrations-otel`) are native connectors of this contract. Relies on audit rows: B2, B5, C1.

| A claim table, one question many probes (0043) | Adopted, with the words property, reading and claim of 0043 | The posture policies, the connectors and the machine probe already judge a fact against controls; the join across classes is what is missing |
| Connect a realm, not an asset | Adopted | The decision a person can make is the realm and its policy; the assets inside are policy and evidence (FR-034) |
| Auto-enrol everything a realm reports | Changed: only from authenticated sources, bounded (FR-034, FR-035) | A forged syslog line or a runaway scope must not fill the register |
| One native connector per cloud | Rejected | Three SDKs and their permission models to maintain; the inventory reads and best-of-breed tools give more, and ingest is typed and pinned (FR-083) |
| Ingest best-of-breed tools | Adopted with a licence rule and a read-only rule (FR-057, FR-058) | They read best and change often; we keep the typed edge and the evidence |
| A graph database for the identity graph | Rejected | The identity keys and the links are relations in the estate store and the SQL of `estate-query`; a graph database is a second store |
| A time-series database for history | Rejected: as-of reads of the evidence branch (0043 FR-025) | Readings are append-only documents; Git already keeps and signs them |
| Freshness as the primary health | Adopted (0043 FR-019) | A cloud asset never goes offline; evidence that is old is what an assessor finds |
| A cloud-side agent in each account (a function that collects) | Rejected | It is software of ours in the realm with rights of its own; the read-only role and the controller's read give the same evidence with nothing resident |
| The controller creates the role it reads as | Rejected (FR-044) | The controller never holds the right to create principals; the administrator applies a module they can read |
| Event streams as stored content | Rejected: digest and count (FR-065) | Content is personal and large; the typed readings are what a control needs |
| Polling only | Changed: change feeds first, polling under a budget (FR-054, FR-062) | Cost and freshness |
| An agent approves a realm | Rejected (FR-006) | An agent proposes; a person approves by hash |

## Acceptance scenarios

1. **Given** a cloud account and a policy, **When** a person approves the plan by its hash, **Then** the connection reads, its assets join by policy with the trust `connected`, and none was approved one at a time, per FR-006 and FR-034.
2. **Given** an agent, **When** it asks to approve a connection, **Then** `E-CONNECT-NOT-PERSON`, and a proposal it made changed nothing, per FR-006.
3. **Given** a connection whose role holds a write permission that the plan does not list, **When** it is verified, **Then** it is `degraded` with `permission-too-broad`, per FR-051.
4. **Given** a scale set whose members come and go, **When** it is read, **Then** the population is one asset with a coverage, each member has `appeared` and `disappeared`, and the readings of a gone member are kept, per FR-036 to FR-038.
5. **Given** a bucket that infrastructure as code does not name, **When** the sources are compared, **Then** the finding `in-cloud-not-in-code` opens and resolves only on evidence, per FR-033 and FR-070.
6. **Given** an ingest source whose tool has a licence that is not permissive, **When** it is run, **Then** `E-INGEST-LICENCE` until a person records a review, per FR-058.
7. **Given** a realm that suddenly holds ten thousand resources, **When** the scan finishes, **Then** the assets beyond the bound are pending and the finding `enrolment-flood` opens, per FR-035.
8. **Given** a provider with a change feed, **When** a setting changes, **Then** the readings it touches become stale at once and one targeted read is queued, per FR-062.
9. **Given** a spent budget, **When** the cadence cannot be kept, **Then** the connection is `degraded` with `budget` and no stale reading is shown as fresh, per FR-055.

## Out of scope

- The product's commands, surfaces and brand: the product's own specification.
- Writing any connector or codec: each is a library with its own spec kit when it is built; this specification governs the contract and the rules.
- Remediation of a realm: a connection reads; a change of a realm is a plan of Desired OS State that a person approves, and no ingest source and no connector writes.
- Any code: every requirement is Deferred until the owner's command-line acceptance run of 0041 has passed.

## Edge cases

- A realm that is in two connections (an account read by a managed-services provider and by its client): each connection has its own policy, key and budget, and an asset read by both has two sources and one identity (FR-031).
- A cloud account that is closed or suspended by its provider: the connection is `degraded` with the provider's code, its assets are not marked absent by one failed read, and a ghost (FR-033) needs the time of the policy (FR-030).
- An asset that two connections give different identity keys: a finding for a person to settle (FR-031).
- A tool whose pinned binary is withdrawn upstream: the pinned download fails its checksum or its address, the ingest is refused and the source is `degraded`; nothing falls back to another version (FR-056).
- A feed that delivers events for a resource outside the policy's scope: counted and dropped (FR-003).
- A budget that renews while a read is half done: the read resumes from its page token and writes once (FR-053).

## Assumptions

- The controller is where connections run, and the connection's key and credentials are the controller's, in its environment, not in the fleet repository.
- A provider's read-only role can be described by data and verified by a probe; where it cannot, the connector says what it cannot verify.
- Provider tools are run from their own commands at a pin; no provider's SDK is linked into commons.

## Open questions

- **OQ-1**: Is `identity-provider` a kind of connection of its own or a `saas-tenant` with a profile? Default: its own kind, because its readings (accounts, multifactor authentication, conditional policies) are the properties most controls need first.
- **OQ-2**: Does a managed-services provider approve a client's connection (a role in the engagement) or does the client? Default: the role is in the engagement (FR-007) and the client's approver is named in it.
- **OQ-3**: Where does the change feed deliver? Default: to the controller's receiver by the path of 0041-telemetry-and-reach that the plan sets up, or to a relay, never to an address a plan does not name.

## UNVERIFIED

- Which providers support each of the three credential kinds of FR-042 for a read-only role today, the exact form of a federation trust for a controller that is not itself a cloud workload, and whether a provider can say the permissions an identity holds without a permission to read policy: none was read in this change.
- The licences of the candidates (the table above) and the output formats they offer at the versions that would be pinned: read from knowledge, not re-read.
- The cost of the inventory reads of each provider and its limits.
- Whether a provider's change feed can deliver to a controller behind a firewall without a public endpoint: not read.
- The schema of OCSF, CycloneDX, SPDX and OSCAL as the codecs would read them: named here, not re-read (commons 0018-standards-first); the OCSF class numbers already in `integrations` records are the only ones used.

## Key entities

- **Connection**: the approved, typed, read-only link to one realm with a policy, a plan and a state.
- **Realm**: the cloud account, tenant, provider organization, cluster or relay a connection reads.
- **Plan**: the typed, hashed description of a connection, with its connect module.
- **Connect module**: the pinned module of OpenTofu that the realm's administrator applies to create the one read-only role.
- **Identity key**: a normalized identifier by which an asset is recognised across sources.
- **Source difference**: a finding that two sources disagree.
- **Population**: an asset that stands for ephemeral members.
- **Ingest source**: a pinned tool or provider read, its argv, its codec and its connection.
- **Change feed**: a provider's stream of change events that makes readings stale at once.
- **Budget**: the calls, bytes and concurrency a connection may spend.
